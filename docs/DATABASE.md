# LR Manager — database design (Phase 3)

Status: **design only**. Migrations come in a later task. PostgreSQL on Supabase, Drizzle ORM schema in
`db/schema/*.ts`, migrations generated by drizzle-kit into `db/migrations/`.

## 1. Ground rules

| Rule                 | How                                                                                                                                                                                                                                                                                             |
| -------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Ids                  | `uuid primary key default gen_random_uuid()`                                                                                                                                                                                                                                                    |
| Tenant               | every business table has `company_id uuid not null references companies(id)`                                                                                                                                                                                                                    |
| Cross-company safety | every parent has `unique (company_id, id)`; every FK between business tables is **composite** `(company_id, x_id) → parent(company_id, id)`, so a row can never point at another company's party/truck/LR                                                                                       |
| Common columns       | `created_at timestamptz not null default now()`, `updated_at timestamptz not null default now()`, `created_by uuid`, `updated_by uuid` (→ users), `cancelled_at timestamptz`, `cancel_reason text`, `version int not null default 1`; check `cancel_reason is null or cancelled_at is not null` |
| Version              | trigger `bump_row()` sets `updated_at = now()`, `version = old.version + 1`, `updated_by = auth.uid()`. App updates with `where id = $1 and version = $expected`; 0 rows → `ConflictError` (same contract as `updateRecord` today)                                                              |
| Money                | `bigint` paise, `check (>= 0)` unless a value can be negative (round-off)                                                                                                                                                                                                                       |
| Weights / qty        | `numeric(12,3)`; Drizzle returns strings = `Decimal` type                                                                                                                                                                                                                                       |
| Rates                | basis points `integer` (500 = 5%)                                                                                                                                                                                                                                                               |
| Dates                | business dates `date`; moments `timestamptz` (UTC). Display dd-mm-yyyy in the app                                                                                                                                                                                                               |
| Deletes              | **no DELETE on business tables** (no RLS delete policy, `revoke delete`). Cancel = set `cancelled_at`                                                                                                                                                                                           |
| Child lines          | lines are part of their parent record: they carry `company_id` + parent FK, no own `version`/`cancelled_at` (the parent's version guards them). Editing a draft replaces its lines in the same transaction; the parent's audit entry records old → new lines                                    |
| Snapshots            | `snapshot jsonb` on LR, tax invoice, freight bill — written once at book/finalise, never updated (trigger blocks changes once set)                                                                                                                                                              |
| Status               | never stored ad hoc. See §5                                                                                                                                                                                                                                                                     |

Drizzle: one helper `businessColumns()` adds the common columns; policies are declared in the schema
with `pgPolicy` from `drizzle-orm` (+ `authenticatedRole`, `authUid` from `drizzle-orm/supabase`), so
drizzle-kit generates RLS with the tables. Things drizzle-kit can't express (triggers, SQL functions,
storage policies, pg_trgm) go in hand-written SQL migrations alongside.

Extensions: `pgcrypto` (already on Supabase), `pg_trgm`.

## 3. Tables

`[B]` = has the common business columns from §1. `→ x` = composite FK with company_id.

### 3.1 Companies & people

**companies** (the tenant itself; no company_id) — id, created_at, updated_at, cancelled_at,
cancel_reason, version

- label, name, city, office, email, website, mobile1, mobile2
- gstin `text not null` (check format), pan `text not null`, udyam
- bank_account_name, bank_name, bank_account_no, bank_ifsc — check all four set or all null (= `bank: null`)
- invoice_title, invoice_note, freight_bill_prefix, tax_invoice_prefix, invoice_round_off bool,
  numbering_resets_yearly bool, freight_gst_rate_bp int (check 0–2800), signatory_name
- lr_prefix `text not null default ''`, jurisdiction, pod_days int, pod_penalty_per_day_paise bigint,
  lr_copies `text[] not null`, detention text, lr_terms text
- logo_path, use_logo_watermark bool, signature_path (Storage paths, §8)
- `nextLrNo` is **not** a column — read from number_series.

**users** — id `uuid primary key references auth.users(id)`, name, mobile (unique where not null),
email, last_login_at, created_at, updated_at, cancelled_at. Not company-scoped. A row is created by
trigger `on auth.users insert`. No password column (Supabase Auth owns credentials).

**memberships** [B] — user_id → users, role member_role

- unique `(company_id, user_id) where cancelled_at is null`
- trigger `keep_one_owner`: refuses an update/cancel that leaves a company with no active owner
  (backstop for `LAST_OWNER_MESSAGE` in `lib/data/members.ts`)

**role_permissions** (lookup, no company_id) — role member_role, action text, PK (role, action).
Seeded from `PERMISSIONS` in `lib/permissions.ts`; a test asserts the seed and the TS map are identical,
so the TS file stays the single source of truth.

### 3.2 Masters

**parties** [B] — name, place, gstin, pan, phone, address, state_code `char(2)`, pincode, logo_path,
default_from, default_payment_mode, default_gst_payer, default_charged_as, source record_source,
is_self bool, search_text (generated, §7)

- unique `(company_id, gstin) where gstin is not null and cancelled_at is null`
- unique `(company_id) where is_self` — one self party per company
- trigger: self party can't be cancelled; its name/gstin/address/phone are synced from companies by
  trigger on companies update (today: `lib/self-party.ts`)

**drivers** [B] — mobile (normalised 10 digits), name, licence_no, licence_expiry date,
user_id → users (null until invited), invited_at

- unique `(company_id, mobile) where cancelled_at is null`; index (user_id)

**trucks** [B] — number (normalised, check `^[A-Z0-9]+$`), driver_id → drivers, rc_expiry,
insurance_expiry, permit_expiry, fitness_expiry, source

- unique `(company_id, number) where cancelled_at is null`

**items** [B] — code, name, hsn, uom, gst_rate_bp, last_rate_paise, search_text

- unique `(company_id, lower(code)) where code is not null and cancelled_at is null`

### 3.3 Numbering

**number_series** — company_id, series number_series_kind, fy `text` (check `^\d{4}-\d{2}$`, e.g.
"2026-27"), prefix text, next_no bigint (check ≥ 1), updated_at. PK `(company_id, series, fy)`.

- `prefix` = the prefix used for numbers in that FY row (copied from the company setting when the row is
  created; Settings updates the current FY row too). Old FYs keep the prefix they printed with.
- Allocation (inside the document's save transaction, never `max + 1`):
  ```sql
  select prefix, next_no from number_series
   where company_id = $1 and series = $2 and fy = $3
   for update;
  -- missing row → insert ... on conflict do nothing, then re-select for update.
  --   start = 1 if (series <> 'lr' and numbering_resets_yearly) else latest FY's next_no;
  --   LR with no row at all → error "Set the next LR number in Company profile first".
  update number_series set next_no = next_no + 1, updated_at = now() where ...;
  ```
  Same rules as `allocateNumber` / `peekNumber` / `raiseNumber` in `lib/data/_store.ts`; `raiseNumber`
  (Settings, Smart import) is an `update … set next_no = greatest(next_no, $n)` under the same lock.
- Numbers are stored twice on documents: display text (`lr_no`) + the counter (`lr_seq`) and its `fy`,
  so uniqueness and sorting don't parse strings.

### 3.4 LR

**lrs** [B] — import_batch_id → import_batches, lr_no text not null, lr_fy, lr_seq bigint,
lr_date date (null while draft), from_place, to_place, risk, consignor_id / consignee_id / billed_to_id
→ parties, gst_paid_by, payment_mode, charged_as, rate_paise, truck_id → trucks, driver_mobile, remarks,
booked_at, dispatched_at, delivered_at, snapshot jsonb, search_text (§7)

- **charges as columns** (fixed set of 9, all `bigint null`): freight_paise, packing_paise,
  cn_charge_paise, loading_paise, unloading_paise, detention_paise, other_paise, gst_paise, advance_paise.
  Balance / grand total stay computed (`lib/lr-charges.ts`).
- **cached lifecycle stamps** (§5): pod_received_at, billed_at, paid_at — written only by triggers
- unique `(company_id, lr_no)` — includes cancelled LRs (the number stays used)
- check `booked_at is null or (lr_date is not null and snapshot is not null)`

**lr_items** — id, company_id, lr_id → lrs, position smallint, item_id → items, description,
packages int (≥ 0), actual_weight numeric(12,3), charged_weight numeric(12,3), size.
unique (lr_id, position).

**lr_invoices** — id, company_id, lr_id → lrs, position, invoice_no, invoice_date, value_paise,
eway_bill_no (check 12 digits), eway_expires_at timestamptz, tax_invoice_id → tax_invoices.
The only LR ↔ tax-invoice link (as in types). unique (lr_id, position).

### 3.5 Tax (goods) invoices

**tax_invoices** [B] — invoice_no (null = own draft), invoice_fy, invoice_seq (own invoices only),
invoice_at timestamptz, status doc_status, seller_party_id → parties (null = this company),
bill_to_id → parties not null, ship_to_id → parties, place_of_supply_state_code char(2),
customer_ref, customer_ref_date, so_no, so_date, do_no, sap_ref, transporter_name, truck_id → trucks,
driver_mobile, ship_from, incoterm, irn, eway_bill_no, source_file_path, import_batch_id,
snapshot jsonb, search_text

- totals as columns: taxable_paise, sgst_paise, cgst_paise, igst_paise, round_off_paise (may be
  negative), total_paise
- unique `(company_id, invoice_fy, invoice_seq) where seller_party_id is null and invoice_seq is not null`
  — own series, cancelled included
- unique `(company_id, coalesce(seller_party_id, '00000000-0000-0000-0000-000000000000'), invoice_fy, invoice_no) where invoice_no is not null`
  — matches `assertUniqueNo` (unique per seller + FY; imported invoices keep the seller's number)
- check `status = 'draft' or (invoice_no is not null and snapshot is not null)`

**tax_invoice_lines** — id, company_id, tax_invoice_id → tax_invoices, line_no smallint, item_id,
item_code, description, hsn, uom, qty numeric(14,3), rate_paise, discount_paise, taxable_paise,
gst_rate_bp, sgst_paise, cgst_paise, igst_paise. unique (tax_invoice_id, line_no).

### 3.6 POD

**pods** [B] — lr_id → lrs, received_by, receiver_phone, packages_received, condition pod_condition,
remarks, document_paths `text[]` (Storage paths; not queried, so no child table), received_at.

- unique `(company_id, lr_id) where cancelled_at is null` — one live POD per LR

### 3.7 Freight bills & payments

**freight_bills** [B] — status doc_status, bill_no (null until final), bill_fy, bill_seq, bill_date,
party_id → parties, gst_mode, gst_rate_bp, snapshot jsonb, search_text

- totals as columns: charges_paise, sgst_paise, cgst_paise, igst_paise, advance_paise, amount_paise
- unique `(company_id, bill_fy, bill_seq) where bill_seq is not null` — cancelled keep their number
- check `status = 'draft' or (bill_no is not null and snapshot is not null)`

**freight_bill_lines** — id, company_id, freight_bill_id → freight_bills, lr_id → lrs, position,
freight_paise, detention_paise, other_paise, advance_paise, total_paise, bill_cancelled_at
(copied from the bill by trigger)

- unique `(company_id, lr_id) where bill_cancelled_at is null` — an LR is on at most one live bill
  (DB backstop for the check in `lib/data/bills.ts`)

**payments** [B] — party_id → parties, amount_paise (> 0), tds_paise (≥ 0), mode receipt_mode,
received_on date, reference. No allocations = on-account advance.

**payment_allocations** — id, company_id, payment_id → payments, freight_bill_id → freight_bills,
amount_paise (> 0). unique (payment_id, freight_bill_id).
Trigger: allocation's bill must belong to the payment's party (backstop for `bills.ts`).

**view freight_bill_balances** (security_invoker) — bill id, received_paise (sum of allocations on
non-cancelled payments), due_paise, paid_on (latest received_on once fully settled). Replaces
`receivedForBill` / `billPaidOn` in `_derive.ts`.

### 3.8 Smart import

**import_batches** [B] — source import_source, file_name, file_path, format import_format,
kind import_kind, mime_type, size_bytes int, created_by → users, detected_as, status import_status,
error, result jsonb (`ImportReadResult`), mapping jsonb, confirmed_columns text[], mapping_name,
row_actions jsonb, count_valid / count_warning / count_error int, created_records jsonb, imported_at.
Index (company_id, created_at desc), (company_id, status).

**import_mappings** [B] — name, columns jsonb (header → field key).
unique `(company_id, lower(name)) where cancelled_at is null`.

### 3.9 Audit

**audit_log** — id uuid, company_id, created_at, actor audit_actor, user_id → users (null when
actor = system), batch_id → import_batches, table_name text, record_id uuid, action audit_action,
changes jsonb (`[{field, old, new}]`).

- check `(actor = 'user') = (user_id is not null)`
- insert-only: no update/delete policy, `revoke update, delete` from `authenticated`
- written by `lib/data` in the same transaction as the change (the existing `writeAudit` helper keeps
  the field-level diff incl. child lines). Imports write `actor = 'system'` with `batch_id`.
- index (company_id, table_name, record_id, created_at desc), (batch_id)

## 4. How the app talks to the database

- Drizzle + `postgres` (postgres.js) through the Supabase pooler (transaction mode, `prepare: false`).
- Every request runs in one transaction that first does
  `set local role authenticated; select set_config('request.jwt.claims', <verified claims>, true)`
  so `auth.uid()` works and **RLS applies to every query** — the app never uses a bypass connection for
  user actions. Claims come from `supabase.auth.getClaims()` on the server.
- `lib/data/*` keeps its current signatures; it also keeps `assertCan` for friendly messages.
  RLS is the hard wall behind it.
- The secret (service-role) key is used only for: migrations, inviting users / resetting passwords
  (Supabase Auth admin API, replaces `resetMemberPassword`'s mock), and the PDF renderer fetching
  Storage files.

## 5. LR status (one place)

`deriveLrStatus` in `lib/lr-status.ts` stays the only rule. It needs 7 stamps; all are now columns on
`lrs`, so no joins are needed to know an LR's status:

| Stamp                                                | Set by                                                                                         |
| ---------------------------------------------------- | ---------------------------------------------------------------------------------------------- |
| cancelled_at, booked_at, dispatched_at, delivered_at | the LR save / POD save                                                                         |
| pod_received_at                                      | trigger on pods (received_at of the live POD)                                                  |
| billed_at                                            | trigger on freight_bills / freight_bill_lines (bill_date of a **final**, live bill)            |
| paid_at                                              | trigger on payments / payment_allocations / freight_bills (paid_on from freight_bill_balances) |

Triggers are `security definer` so an accountant recording a payment can update the LR stamps
without `lr.edit`.

For the register's status filter and dashboard counts, `lib/lr-status.ts` gains
`lrStatusWhere(status)` that returns the Drizzle condition for each status (e.g. "In transit" =
`cancelled_at is null and booked_at is not null and paid_at is null and billed_at is null and
pod_received_at is null and delivered_at is null and dispatched_at is not null`). A test runs every
combination of stamps through both `deriveLrStatus` and `lrStatusWhere` (against the DB) and asserts
they agree. Same file, one rule.

Tax invoice display status ("cancelled" wins) stays in `lib/invoice-status.ts`.

## 6. Row Level Security

RLS on for **every** table (incl. lookups: read-only). Helpers in schema `app`, all
`security definer stable set search_path = ''`:

- `app.role_in(company uuid) → member_role` — active membership of `auth.uid()` in an active company
  (uses the unique (company_id, user_id) index)
- `app.can(company uuid, action text) → bool` — `role_permissions` lookup
- `app.is_office(company uuid) → bool` — member and role ≠ driver
- `app.my_driver_id(company uuid) → uuid` — drivers.id where user_id = auth.uid()
- `app.is_own_trip(company uuid, lr uuid) → bool` — LR's driver_mobile = my driver's mobile, or LR's
  truck has me as driver (same rule as `assertPodAccess` in `lib/data/pod.ts`)

| Table(s)                                                   | SELECT                             | INSERT / UPDATE                                                                                                                                                        |
| ---------------------------------------------------------- | ---------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| companies                                                  | member                             | update: `company.manage`. Insert only via `app.create_company()` (definer fn: company + owner membership + self party + number_series rows, one transaction)           |
| memberships                                                | own row, or `is_office`            | `company.manage`                                                                                                                                                       |
| users                                                      | self, or shares a company with you | self (name/mobile); rest via Auth trigger                                                                                                                              |
| parties, trucks, drivers, items                            | `is_office`                        | `master.edit`                                                                                                                                                          |
| lrs, lr_items, lr_invoices                                 | `is_office` and `freight.view`*    | `lr.edit`; update also `pod.upload` / own trip (column guard below)                                                                                                    |
| tax_invoices, tax_invoice_lines                            | `is_office`                        | `invoice.edit`                                                                                                                                                         |
| freight_bills, lines, payments, allocations, balances view | `freight.view`                     | `bill.edit`                                                                                                                                                            |
| pods                                                       | `is_office`, or own trip           | `pod.upload`, or `pod.upload_own` and own trip                                                                                                                         |
| import_batches, import_mappings                            | `import.run`                       | `import.run`                                                                                                                                                           |
| audit_log                                                  | `is_office`                        | insert: member and (`user_id = auth.uid()` or system with a batch you created)                                                                                         |
| number_series                                              | `is_office`                        | none directly — only through allocation inside the save txn (update policy: `lr.edit` / `invoice.edit` / `bill.edit` for the matching series; raise: `company.manage`) |
| role_permissions                                           | any authenticated                  | none                                                                                                                                                                   |

\* every office role has `freight.view` today; the policy names it so a future role without it works.

Extra guards (triggers, because RLS is per row, not per column):

- **Cancel guard** on every [B] table: changing `cancelled_at` needs `record.cancel`
  (memberships: `company.manage`, matching `removeMember`).
- **LR column guard**: a user without `lr.edit` may only change `delivered_at` (POD flow, booking-
  staff/driver), and a driver only on their own trip.
- **Drivers** don't read `lrs` directly (they have no `freight.view`): the driver app uses
  `app.my_trips()` (definer fn) that returns their trips without money columns.
- Line tables: DELETE allowed (draft line replacement) only when the parent is a draft / editable and
  you have the parent's edit permission. No DELETE anywhere else.

## 7. Indexes (per screen)

Search uses `pg_trgm` GIN on a lower-cased `search_text`. Where all parts live on the row it is a
`generated always as (...) stored` column; where it needs names from other tables it is kept by
trigger (and refreshed when a party name / truck number changes).

| Screen / query                                                              | Index                                                                                                                                                |
| --------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------- |
| every table                                                                 | `(company_id, id)` unique (composite FKs) + an index on every FK column                                                                              |
| LR register search (LR no, party names, truck, places, invoice / e-way nos) | `gin (search_text gin_trgm_ops)` on lrs (trigger-kept)                                                                                               |
| LR register default sort                                                    | `(company_id, created_at desc)`                                                                                                                      |
| LR date range                                                               | `(company_id, lr_date)`                                                                                                                              |
| LR by party / truck                                                         | `(company_id, consignor_id)`, `(company_id, consignee_id)`, `(company_id, billed_to_id)`, `(company_id, truck_id, created_at)`                       |
| LR status filter / dashboard open LRs                                       | partial `(company_id, created_at desc) where cancelled_at is null and delivered_at is null`                                                          |
| POD pending / overdue                                                       | partial `(company_id, delivered_at) where delivered_at is not null and pod_received_at is null and cancelled_at is null`                             |
| Unbilled TBB                                                                | partial `(company_id) where payment_mode = 'tbb' and booked_at is not null and cancelled_at is null` + live-line unique on freight_bill_lines(lr_id) |
| Repeat routes                                                               | partial `(company_id, consignor_id, consignee_id, lr_date desc) where booked_at is not null and cancelled_at is null`                                |
| E-way alerts                                                                | partial `lr_invoices (company_id, eway_expires_at) where eway_bill_no is not null`                                                                   |
| Driver trips                                                                | `lrs (company_id, driver_mobile)`                                                                                                                    |
| Parties search / sort                                                       | generated search_text (name, place, gstin, phone) GIN trgm; `(company_id, lower(name))`                                                              |
| Trucks / drivers search                                                     | trucks `gin (number gin_trgm_ops)`; drivers generated search_text (name, licence, mobile)                                                            |
| Doc expiry alerts                                                           | trucks partial `(company_id, rc_expiry)` / insurance / permit / fitness `where cancelled_at is null`; drivers `(company_id, licence_expiry)`         |
| Items search / pick-list                                                    | generated search_text (code, name, hsn) GIN trgm; `(company_id, lower(code) text_pattern_ops)` for code-prefix                                       |
| Tax invoice list                                                            | `(company_id, invoice_at desc)`, `(company_id, status)`, `(company_id, bill_to_id)`, search_text (no., bill-to name, GSTIN, linked LR nos)           |
| Bills list                                                                  | `(company_id, bill_date desc)`, `(company_id, party_id)`, `(company_id, status)`, search_text (no., party, LR nos)                                   |
| Payments                                                                    | `(company_id, party_id, received_on desc)`; allocations `(company_id, freight_bill_id)`                                                              |
| POD received list                                                           | pods `(company_id, received_at desc)`                                                                                                                |
| Membership / RLS lookups                                                    | memberships unique `(user_id, company_id) where cancelled_at is null`                                                                                |
| Audit / LR activity                                                         | `(company_id, table_name, record_id, created_at desc)`                                                                                               |

## 8. Storage

Four **private** buckets. Object path always starts with the company id:
`{company_id}/{record_id}/{uuid}-{file name}`.

| Bucket     | Holds                        | Limit / types                         | Read                     | Write                                              |
| ---------- | ---------------------------- | ------------------------------------- | ------------------------ | -------------------------------------------------- |
| logos      | company logo, party logos    | 2 MB · png, svg, jpeg                 | `is_office`              | `company.manage` (company) / `master.edit` (party) |
| signatures | signature / stamp            | 2 MB · png, svg, jpeg                 | `is_office`              | `company.manage`                                   |
| pod        | signed LR copies, POD photos | 3 MB · image/*, pdf                   | `is_office`, or own trip | `pod.upload`, or `pod.upload_own` + own trip       |
| imports    | Smart import originals       | 10 MB · xlsx, xls, csv, pdf, jpg, png | `import.run`             | `import.run`                                       |

Policies on `storage.objects` check `(storage.foldername(name))[1]::uuid` with the same `app.*`
helpers. Tables store the **path**; `lib/data` turns it into a short-lived signed URL when reading,
so UI fields like `logoUrl` keep working. Files are never deleted (cancelled records keep theirs).
SVGs are served with `Content-Disposition: attachment` except through `<img>`.

## 11. Deliberate choices to confirm

1. **LR charges as 9 columns**, not an lr_charges table (fixed set, always read together).
2. **Unique truck number / GSTIN / driver mobile only among non-cancelled rows**, so a cancelled
   truck can be added again. LR, invoice and bill numbers are unique **including** cancelled ones.
3. **Tax-invoice uniqueness includes the seller** (own series + imported sellers' numbers), which is
   what the current code enforces; the plain `(company_id, series, fy, no)` would block two sellers
   sharing a number.
4. **Audit written by the app** (keeps today's field-level diffs incl. lines), DB makes it insert-only.
5. **New libraries when we build it** (not now): `drizzle-orm`, `drizzle-kit` (schema/migrations),
   `postgres` (driver), `@supabase/supabase-js` + `@supabase/ssr` (Auth + Storage in Next.js). All are
   the stack named in CLAUDE.md.
